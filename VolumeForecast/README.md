# Volume Forecast Data Workflow

The current workflow uses `VolumeForecast.xlsx`, sheet `Data`, as the local source. The Power BI DAX query remains optional because the report is connected to a remote semantic model and API access is not required for local analysis.

## Prerequisites

- Windows PowerShell 5.1 or PowerShell 7
- Microsoft Excel installed locally, because the script reads the workbook through Excel's COM interface
- `VolumeForecast.xlsx` at the repository root, unless another path is supplied

## Run the local Excel workflow

From the repository root:

```powershell
.\scripts\analyze-volume-forecast.ps1
```

## Refresh the data

The script reads the last saved state of the workbook. To refresh the source data first:

1. Open `VolumeForecast.xlsx` in Excel.
2. Select `Data > Refresh All`.
3. Wait for the refresh to finish.
4. Save the workbook.
5. Close Excel if the workbook is locked by another process.
6. Run the PowerShell script again.

The script then regenerates all files under `output` from the refreshed `Data` tab. If Excel reports a credential or connection error, resolve that in Excel before running the script.

The current default filter profile is:

- `ProductGroupNm`: `NOVA LAKE`, `RAZOR LAKE`
- `MfgLocationStage`: `TEST`, `FINISH`

These are defaults for the current analysis, not fixed business rules. Choose different product groups or stages with the script parameters when needed.

Outputs are written to `output`:

- `volume-forecast-filtered.csv`: primary row-level dataset for current and future analysis
- `volume-forecast-summary.csv`: optional convenience summary, quantity summed by quarter, product, milestone, and stage
- `volume-forecast-query.dax`: equivalent optional query for Power BI Desktop
- `volume-forecast-validation.json`: source path, row counts, filters, total quantity, and generation time

Use `volume-forecast-filtered.csv` as the main input for downstream analysis. The summary CSV is not required and can be ignored when row-level detail is needed.

To use different filters:

```powershell
.\scripts\analyze-volume-forecast.ps1 `
    -ProductGroups 'NOVA LAKE' `
    -Stages 'TEST', 'FINISH'
```

To use another workbook or output folder:

```powershell
.\scripts\analyze-volume-forecast.ps1 `
    -WorkbookPath 'C:\path\to\VolumeForecast.xlsx' `
    -OutputDirectory 'C:\path\to\output'
```

## Optional Power BI path

Open `output\volume-forecast-query.dax` in Power BI Desktop DAX Query View when the semantic model is available. The query returns raw rows from `factSnOPdata`; it does not create a CSV by itself. Export the results manually from Power BI Desktop or use the local CSV generated by the script.

To refresh the Power BI side separately, open the PBIP/report in Power BI Desktop, select `Home > Refresh`, and rerun the DAX query. Power BI refreshes do not update `VolumeForecast.xlsx` automatically; the Excel refresh and Power BI refresh are separate paths.

## Data assumptions

The script expects the `Data` sheet to contain these columns:

`ProductGroupNm`, `DesignItemDsc`, `RevStepCd`, `SpeedDesignId`, `YearQuarterTxt`, `YearMonthTxt`, `MfgLocationCd`, `DesignItemMilestone`, `MfgLocationStage`, `KF_Qty`.

It locates the header by name, so leading blank rows and a non-A1 used range are allowed. Aggregate footer rows such as `Grand Total` are excluded. `KF_Qty` is read from Excel's underlying value; invalid or blank quantities are treated as zero and recorded in the generated output as zero.
